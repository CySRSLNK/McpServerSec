# ChainBreak — MCP 跨服务器组合调用的安全性判定
[![M8ven Score](https://m8ven.ai/badge/mcp/cysrslnk-mcpserversec-tef2a9?v=f700db75a3d9b59e8d4fbfd5eb54caff)](https://m8ven.ai/mcp/cysrslnk-mcpserversec-tef2a9?s=readme)
给定部署 `D` 与安全属性 `G`，判定 `D ⊨ G`，输出三态：**UNSAFE / SAFE / UNKNOWN**。

安全 = **不泄露信息** ∧ **不被不可信内容诱导执行特权动作**。

---

## 一键运行（交付版）

```bash
python3 deliver.py                 # 跑完 10 个场景，写 report.md 与 reports/*.smv
python3 demo.py                    # 讲解版：为什么单个安全、组合不安全
python3 -m unittest discover -s tests -v    # 32 条断言
```

纯标准库、零网络、零 API key。Python 3.10+，在 3.13 上验证。

`deliver.py` 会输出：

```
编号  场景                                    覆盖         判定      期望     结论
01    search 恶意页面 → 诱导 upload 传走 .…   INJECT       UNSAFE    unsafe   ✓
02    search 单独运行                          search       SAFE      safe     ✓
...
UNSAFE 6 个 / SAFE 4 个 / 期望不符 0 个
```

每条发现自动标注**局部缺陷**还是**组合漏洞**——把见证里的服务器逐个单独跑一遍，
单台能复现就标"局部"。这条检查能挡住最常见的质疑："你这条违例单台也能复现，凭什么叫组合漏洞？"

## 核心场景：search 恶意页面 → 诱导 upload 传走 .env

| 服务器 | 本地策略 |
|---|---|
| `search` | 只检索，不外发本地数据 |
| `envfs` | 只读允许目录 |
| `upload` | 只把调用方给的内容传到调用方给的地址 |

| 检查范围 | 判定 |
|---|---|
| search 单独 | ✓ SAFE |
| envfs 单独 | ✓ SAFE |
| upload 单独 | ✓ SAFE |
| **三者组合** | ✗ **UNSAFE** |

```
1. search.search        页面返回不可信内容，进入上下文
2. envfs.read_file      读出 .env（敏感）
3. upload.upload        把敏感内容发往页面指定的地址   ← 同时违反 F1 与 F7
```

### 两个属性必须分开

| 属性 | 刻画 | 谁发起都一样？ |
|---|---|---|
| **F1 敏感数据外泄** | 数据层面：秘密不该出去 | 是 |
| **F7 注入驱动外联** | 控制层面：指令不该来自页面 | 否 |

`envfs+upload`（无 search）也违反 F1——数据流上同样泄露，但没有攻击者。
**纯数据流检测会把"用户自己要求上传 .env"也判成违规**，所以 `G` 必须是两者的合取。

### 半吊子防御都不够

| 防御 | F1 | F7 | 判定 |
|---|---|---|---|
| 无防御 | ✓ | ✓ | UNSAFE |
| 只做数据标签 | · | ✓ | UNSAFE |
| 只做影响污点 | ✓ | · | UNSAFE |
| **两者都做** | · | · | **SAFE** |

只堵一条，另一条仍然成立——这是**组合性质**，不是单点缺陷。

## 三条通道

| 通道 | 载体 | 协议里有标签吗 |
|---|---|---|
| 参数边（模式A） | 调用参数 | 无 |
| 上下文边（模式B） | Agent 上下文 | 无 |
| 存储边（模式C） | 共享介质（文件系统/记忆图） | 无 |

同一跳里控制流与数据流可以走不同通道（`docs/COMPOSITION.md`）。

---

## 三态判定

| 判定 | 条件 | 证据强度 |
|---|---|---|
| **UNSAFE** | 找到全合规反例 | 见证即证据 |
| **SAFE** | 状态空间穷尽、无反例 | 相对模型与过近似抽象的证明 |
| **UNKNOWN** | 触达状态上限 | 既不能说不安全，也不能说安全 |

前提：(a) 抽象是过近似，`SAFE` 才可靠；(b) `SAFE` 只相对被检验的属性集合。
所以问句必须写成 **`D ⊨ G`**，而不是「组合是否安全」。

## 7 类属性

F1 敏感数据外泄 / F2 不可信内容驱动特权动作 / F3 权限域放大 / F4 来源丢失洗白 /
F5 注解谎报·影子工具 / F6 失效句柄仍被接受 / F7 注入驱动外联。

其中 **F4 在任何客户端策略加固后依然存在**：provenance 一旦丢失，客户端补不回来。

---

## 不能证明什么

1. 标签是抽象格，只能给 may-dependency；
2. **F7 用「上下文含不可信内容」近似「指令来自不可信内容」，会误伤正常链式操作**；
3. 上下文压成单一 join 标签，丢失逐条目粒度；
4. 服务器 EFSM 由模板实例化，不是从真实实现自动学习；
5. 跨会话传播未建模；
6. 单服务器隔离检测模拟的是该服务器的测试套件，不是全部行为；
7. `SAFE` 只相对被检验的属性集合。

第 2、6、7 条是答辩必被问的，必须主动写进「限制」。

---

## 避免过度声称

「局部安全不构成全局安全」**不是新发现**——Lampson 1973 的 confinement problem、
DIFC（Myers & Liskov 1997）都在处理它。

可辩护的贡献：
1. MCP 的**标签不透明**如何使条件必然成立，且 **Agent 本身就是 declassifier**；
2. **数据流属性与指令来源属性的分离**；
3. 三条通道的统一刻画，支持混合通道链；
4. 三态判定 + 可回放见证 + 局部性标注。
